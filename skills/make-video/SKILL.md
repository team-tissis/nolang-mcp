# Make a NoLang video

Pass the request to `nolang make`. The script and the screens (draft src) are written with the same procedure as the NoLang studio (as soon as the author writes each cut, it is checked and fixed, then submitted), and the NoLang server handles the voice, pictures, BGM and rendering. You do not need a GPU or the NoLang repo on your machine.
All paths in this file are relative to this skill's directory.

**Running the CLI (`nolang` below)**: in Claude Code it is `node ${CLAUDE_PLUGIN_ROOT}/cli/nolang.mjs <args>` — the plugin does not put `nolang` on PATH, so never run a bare `nolang` and do not probe with `which` / `command -v`. Run every call as one plain command with that full path written out (no shell variables, `$(...)`, `||`, `&&`, `;` or pipes), so the user gets a readable permission prompt they can allow once. In Codex, use `../../cli/nolang.mjs` from this skill's directory, made absolute, the same way. Put text you pass as an argument (the request text, a title) in **single quotes** (`'…'`): inside double quotes the shell runs any `` ` `` or `$(…)` in the text. If the text itself contains a `'`, write it to a file and pass the file (`--request <file>` for `nolang make` / `nolang edit`).

## Most important: give the video link right away, and never leave it out

The user cannot see command and tool output. Whether the user can open the video depends only on the link you write in your message.

- If the output has `tell_user`, write that text (the guidance sentence + the URL line) **as is** in your message to the user **before you call the next tool**. Do not leave it out, do not summarise it, do not just report the seconds or the status, and do not write "the link above".
- `tell_user` comes in the user's language (the language the user chose on the NoLang login screen — Japanese for Japanese speakers, English for everyone else). When the user is speaking a language that is neither of these, translate it into that language (keep the URL line as is).
- The same applies when you make a test video, measure speed, make several videos in a row, or wait until completion. When you continue working, write the link first, then continue.
- Write the video's URL again in your last message too (the completion report, the failure report, or the summary).
- **Format**: Put a line break before and after each URL (the watch URL `watch_url`, the login `authorize_url`, the mp4 `download_url`), and **write only that URL on its own line**. Do not put text, brackets, punctuation or markdown decoration (`**` or `[]()`) before or after it, and do not put it in a table cell (so it can be clicked and opened as is). `tell_user` text is already in this form, so write it as is, line breaks included.

## ¥. Cost and balance (when asked about pricing, when told 「お金がかかるなら先に」 ("if it costs money, tell me first"), or when the user may be on the free plan)

- `nolang account` (`nolang_account` on MCP) — shows the plan, the balance `remaining_credit`, free video generation `has_free_video_generation` (whether a video can be made with the free plan's free credit; if true, it can be made without using credit), the billing method, the credit per minute of length `credit_per_minute`, the balance needed to start a video `minimum_credit_per_video` (not a minimum charge), and whether a video can be made now `can_generate`. It consumes nothing. Estimated cost = requested length (minutes) × `credit_per_minute`. With the normal billing method, the charge is settled after generation based on the actual length and the AI usage, so it can be higher or lower.
- If `can_generate: false`, do not make the video. Pass on `tell_user` (the reason, and the URL of the page that resolves it) and stop. The URL is the one that matches `blocked_by` — `INSUFFICIENT_CREDIT` → `credit_url` (top up credit), `PLAN_UPGRADE_REQUIRED` → `plan_url` (change plan) — and once the user completes it there, videos can be made (`MEMBER_CREDIT_LIMIT_EXCEEDED` has no URL: the monthly limit is set by the organization's admin, so the user asks the admin). Always write it on its own line ("Format" above). `nolang make` runs the same check itself before it starts, and stops with `error_code` (`INSUFFICIENT_CREDIT` / `PLAN_UPGRADE_REQUIRED`) if a video cannot be made.
- Rules such as the price list, plans, commercial use and retention period are on the NoLang website: pricing https://no-lang.com/pricing , terms https://no-lang.com/terms , FAQ https://no-lang.com/faq . Do not answer by guessing what you do not know; read these pages or point the user to them.
- If running `nolang make` stops at a permission prompt (a long video may be treated as a real transaction), ask the user for permission and mention the estimated cost (the `account` values above) in a few words.

## 0. Which way to make it

- **The default is the studio** (§S): if you have a shell, `node` (20 or later) and an execution engine, run `nolang make` once. You do not write the draft.
- **In Claude Code**: if `claude` is available, run `nolang make` (no engine specified). The author, staff and fixer are Claude. Playback starts in about a minute and a half.
- **In Claude Code without a `claude` command** (`make_engines` in the output of `nolang auth status` has no `claude` — the Claude desktop app's Code tab without the CLI installed, Cowork), or when `nolang make` fails because the local `claude` cannot run: run `nolang make ... --engine host` from the start and follow `host-engine.md` — your own subagents take the author, staff and fixer roles, with the same steps and modes.
- **In Codex**: prefer `nolang make ... --engine codex`, even when subagents are available. `make_engines` in `nolang auth status` shows which CLI commands are installed; `make` checks the Codex CLI's authentication before starting. If `codex` is absent, or `make` reports missing `auth.json` / unavailable Codex authentication before starting a video, use `--engine host` when the shell and subagents are available, following `host-engine.md`. Do not read or display credentials, and do not switch to Claude.
- **When in a hurry and no detailed polish is needed**: `nolang generate --request-text '<request text>' --idempotency-key <key> [--aspect] [--seconds]` — the NoLang server writes the script and the screens (the same as the web home page; it does not use the studio, so your local LLM (the user's own Claude Code / Codex) incurs no cost).
  - You do not need to give the video language (it is decided in this order: stated in the request → the reference video → the language of the request text). Add `--video-language <en etc.>` only when the video should be in a language different from the request text.
  - Create a new key for each request (a uuid etc.). When you call again after losing the response, or resend with `--confirmed`, use the same key as the first call (so videos are not duplicated). `stage: in_progress` = the server is still evaluating a request with the same key — wait about 30 seconds and call again with the same key.
  - If `stage: unsupported`, show the `blockers` to the user; to make it anyway, resend with `--confirmed`.
- When neither the preferred engine nor the host fallback above is available, or you are told that `nolang make` cannot be used, use `nolang generate`, or "A" in `write-yourself.md` (write the draft yourself and stream it with the CLI). The `claude` / `codex` engines start the user's own local CLI (the host engine uses this session's subagents instead). With the Claude CLI that needs a claude.ai subscription login: when Claude Code runs on an API key, Bedrock or Vertex, `nolang make` cannot write the draft — use `nolang generate`.
- **When there is no shell (claude.ai, ChatGPT, etc.) or the CLI does not run**: §C (MCP). The default is to write the draft yourself and pass it with `nolang_draft_submit` ("B" in `write-yourself.md` — it costs less credit). Use `nolang_create_video` (the server writes it) only when in a hurry.
- **You ask for the login** (the user does not need to know about logging in): when you receive a request, run `nolang auth status` once before making anything (on MCP, call `nolang_account` once). If not logged in, complete the login with §L (on MCP, B in `write-yourself.md`) before going on. If a command exits with code 3 because the NoLang login is missing or expired, log in the same way and then retry. Code 3 about Codex authentication or `auth.json` is a different prerequisite: follow the host fallback above, not the NoLang login flow.

## S. Make it with the studio (default)

1. **Log in**: §L.
2. **Decide from the request**: the genre (`explain` — it explains something: a concept, numbers, a comparison, steps / `film` — a story or a visual-led piece: a narrative, a trailer, a brand film; the pictures lead and the screen carries few elements), the mode (below), the aspect (`16:9` by default; `9:16` only when the request itself says vertical / portrait / Shorts / Reels / TikTok — a short length such as 30 or 60 seconds is not a request for vertical), and the length (if the request states it, those seconds; otherwise auto = fit to the content). Do not ask back; proceed with the defaults, and tell the user the values you chose at the end. Only when there are specific assets (this photo, this song, this voice), get a `ref` with §M.
3. **Make it**: `nolang make ./nolang-videos/<lowercase-english-name> --genre <genre> --mode <mode> --aspect <aspect> --request-text '<request text>'` (add `--seconds <seconds>` only when the length is stated; set the Bash timeout to 600000).
   - **You do not need to give the video language**: if the request text specifies a language (for example 「英語で」, "in English"), that language is used; otherwise the language of the request text (when that cannot be decided, the user's language). So pass the request text in the user's own words, and do not rewrite it in another language. Only when you want to force a language, use `--language <code>` (`ja` `en` `ko` `zh-Hans` `es` …). A request to change the user's own language, such as 「これからは英語で」 ("from now on, in English"), is `nolang account --language <code>`.
   - In Codex, prefer `--engine codex`; use `--engine host` only for the fallback in §0, with the start-and-wait steps of `host-engine.md`. In Claude Code, the engine follows §0.
   - Request text = the user's request as is + the values you decided + the assets' `ref` (`id=<uuid>` and where to use it) + any script or caption wording, as is. If facts about the topic are needed, research them first and write them into the request text (the author does not research). Write everything you add in the same language as the user's request (the video language follows the request text).
   - **Choose `--mode` by what the video is built on**: `standard` when it should stay on one big figure from start to end — one chart whose line grows, one diagram that gains a part per scene, one map (a single author writes every cut, so that figure stays the same across cuts); `plus` otherwise — each cut is designed on its own, so every scene gets its own picture (playback starts 20–40 s later). A `film` is `plus`. Use `light` (fastest, lower quality) or `super` (best quality, 6–10 minutes until playback starts) only when the user asks for speed or for the best quality. For the values and meanings when you set roles individually (author `--author`, staff `--staff`, fixer `--fix`, review `--review`), read `nolang make --help` (the CLI is updated together with the server, so this file does not keep a table of flags).
   - For a video the user wants to adjust in the NoLang editor after generation, use `--editable` — it writes within the grammar subset the editor can handle (number of elements, motion presets, etc.) (expression becomes less dense).
   - For a video made from recorded speech (a talk, interview or lecture recording) — clips, a summary of the key points, shorts — use `--speech <audio file or id>` (add `--speakers N` if you know the number of speakers). The server transcribes it and cuts and uses that audio (the voice stays as recorded). The length is decided by the audio (add `--seconds` if there is a rough target). It waits for the transcription, so it takes a few minutes until playback, and for a long recording that can be longer than the shell's 10-minute limit. If the call is cut off, or returns `ok: false` without a `watch_url` because the wait ran out, the run is still going in the background: read `<dir>/stream/run.out` until a `WATCH <url>` line appears, and pass that URL on. In the request text, write "which parts to use and what to cut (fillers, restarts)".
   - It returns as soon as the server reaches a playable state (for Claude, a little over 1 minute at the default (balanced), about a minute and a half with `--staff medium`, about 1 minute with `--staff none`; Codex speed depends on the model and the request). Generation continues in the background until the end. If generation is still running after the wait time (9 and a half minutes for super, 7 minutes for the others), it returns `still_generating: true` and the watch URL (this is not a failure; write `tell_user` and finish).
   - **The number of videos that can be generating at the same time is limited by the plan** (2 for free / standard, 5 for premium and business. It counts your own videos, not those of business colleagues. The actual value is `concurrent_video_limit` from MCP `nolang_account`). `nolang make` returns once the video is playable, but the video counts as generating until it is complete. When making several in a row, if you get the limit error (`CONCURRENT_GENERATION_LIMIT`, 「同時に作れる動画の数の上限」 "limit on the number of videos that can be made at the same time"), wait for the previous video to complete with `nolang status <previous video_id> --wait --timeout 540` before starting the next (without `--timeout` it waits up to 15 minutes, longer than the shell allows; when it returns still generating, run it again).
4. **Notify** (top priority; "Most important" at the top): **write the output's `tell_user` (the guidance sentence + the URL on the next line) as is in the body of your message to the user**, before you call the next tool. With the host engine, keep the session open until every subagent has finished. Otherwise, if nothing else was asked, end the turn there. Check for completion only when asked (`nolang status <video_id> --wait --timeout 540`, run again while it is still generating → on `completed`, the URL, the mp4 `download_url`, and `copyright` = the credit notice for the BGM, voices and assets. It must be shown when the video is published, so pass it on together).
5. **On failure** (`ok: false`): tell the user the `error` and, if present, the `watch_url`. The cause can be found from `error` and `run_tail` (the end of the engine output). When the server refused to start, `error` reads 「サーバーが生成の開始を断った (error_code): …」 ("the server refused to start generation (error_code): …") — insufficient credit (`INSUFFICIENT_CREDIT`) and insufficient plan (`PLAN_UPGRADE_REQUIRED`) will not be fixed by waiting, so pass on the output's `tell_user` (which includes `fix_url`, the URL of the page that resolves it) as is and stop. For the concurrent generation limit, wait as in the step above. When `--engine host` fails, first check that the workers started and that their files arrived (`host-engine.md`). With the `claude` / `codex` engines, if `error` says the author did not write the structure (「著者が構成を書かなかった」; it mentions the `claude` login or usage limit) and has no `error_code`, the local engine could not run (not logged in to a claude.ai subscription, an API-key / Bedrock / Vertex setup, or the usage limit) — do not retry; make it with `nolang generate`. When the selected engine is unavailable before a video starts, follow the host fallback in §0 first; if that is unavailable too, use `nolang generate` or A in `write-yourself.md`. Remake the same request at most once, in a different dir. Do not make test videos to look for the cause.

## R. Fix a finished video (when asked 「この動画のここを直して」, "fix this part of this video")

The original video stays as it is, and the fixed video is created at a new URL. The target is the `video_id` (the UUID in the watch URL).

1. `nolang edit <dir> <video_id> --request-text '<what to fix>'` (dir is a new empty dir; in Codex, `nolang edit` needs `--engine codex`; when only the host engine is available, remake from the video as a reference with `nolang make`, as `host-engine.md` says) — starting from the saved draft (if there is none, one reconstructed from the video), the editor rewrites only what the request asks for, and the cuts and voices it does not touch pass through unchanged (1–3 minutes until playable). A request that amounts to a remake (length, aspect, converting the overall style) automatically falls back from here to a remake that uses the original video as a reference. The language stays the same as the original video. If the request states an aspect (for example 「縦 9:16 に作り直して」, "remake it vertical, 9:16"), it is remade in that aspect; if not, it keeps the original video's aspect. If `ok: true`, pass on the output's `tell_user` and you are done. For `no_change: true` (there is nothing to patch), pass on the per-item judgement `verdict`.
2. Only when `nolang edit` fails without making a new video, write `[video:<video_id>]` in the request text and run `nolang make` (a remake with a reference).

## C. When there is no shell (MCP)

There are two ways to make it. For connection and authentication, see "Check the connection" in B of `write-yourself.md`.

- **Default = write the draft yourself**: follow §1 and "B" in `write-yourself.md`, and pass the draft you wrote with `nolang_draft_submit`. The NoLang server checks and fixes it. You do not pay for the LLM that writes the script and the screens, so it costs less credit than `nolang_create_video` below.
- **When in a hurry, or when you cannot follow the writing rules = have NoLang write it** (the same entry point as `nolang generate`):

1. **Make it**: `nolang_create_video(text, idempotency_key, aspect_ratio?, duration_s?, video_language?)` — text = the same request text as step 3 of §S (a reference video is `[video:<id>]`). If you omit `video_language` (the video language), it is decided in this order: stated in the request → the reference video → the language of the request text. `idempotency_key` is a new string for each request (a uuid etc.) — use the same key when you call again after losing the response or after a timeout, and when you resend with `confirmed=true` (so videos are not duplicated).
2. **Branch on `stage`**: `accepted` → pass on `watch_url` right away ("Most important" at the top); `unsupported` → show the `blockers`, and to make it anyway, resend with `confirmed=true`; `clarify` → ask the user the `questions`, add the answers to text and submit again; `blocked` → a request that cannot be made (pass on the `blockers`); `in_progress` → the server is still evaluating a request with the same key — wait about 30 seconds and call again with the same key.
3. **Status** (only when asked): `nolang_video_status(video_id)` — if `running`, wait about 30 seconds and call again. On `completed`, you get the mp4 `download_url` and `copyright` (the credit notice for the BGM, voices and assets — it must be shown when the video is published, so pass it on together).
4. **Fix**: `nolang_edit_video(video_id, text)` — the original video stays as it is, and the fixed video is created at a new URL. The language and aspect stay the same as the original video — to change the aspect, ask `nolang_create_video` with `[video:<video_id>]` and the aspect (in `aspect_ratio` or in the request text).
- For cost see §¥ (`nolang_account`); for asset search see §M (`nolang_assets_search`).

## L. Login (both when asked 「NoLang にログインして」, "log in to NoLang", and before making a video)

`nolang auth status`. Exit code 0 means logged in (if login succeeds but NoLang still cannot be used — terms not accepted, balance — `nolang doctor` reports the reason separately). If 3 (not logged in), start the login yourself:

- `nolang auth login --background --language <code of the language the user is speaking: ja / en / ko / zh-Hans / es …>` (returns immediately). With `--language`, the NoLang login screen and its guidance appear in that language, and it becomes the initial value of the "Language" field on the screen (the language the user chooses there becomes the default for later guidance and for video language). **First thing in your next message**, write the output's `tell_user` (the guidance text with the URL, the validity period, and the code for device authorization) as is **in the body of your own message**. On a local machine, the browser opens the login screen and the user only has to press "Allow" (no code entry). With device authorization (SSH, containers, etc.), the user opens the URL, enters the `user_code` to confirm that this is a login they started, and allows it. Do not leave out the code. After you have passed it on, you may decide the content of the request while waiting.
- If the user says they cannot proceed with browser authorization (the browser is only on another machine, or after allowing they get a connection error and cannot even paste the URL), retry with `nolang auth login --background --device --language <same code>` (the code-entry method).
- **After `auth login --background`, write `tell_user` in your message and end the turn** — do not wait first (the user cannot see the URL and the code until you write them). When the user says 「許可した」 ("I allowed it"), run `nolang auth wait` (up to 120 seconds; exit code 0 means done), then go on to the make command or the asset command. If it still returns exit code 3 with `"waiting": true`, the login has not been allowed yet: write the `authorize_url` and, for device authorization, the `user_code` in the body again (do not write "the URL above") and end the turn again. If it returns exit code 3 without `waiting` (the login failed or expired — the reason is in `error`), start over with `auth login --background`.
- If any command exits with code 1 and `TERMS_AGREEMENT_REQUIRED` (403) → the login succeeded, but the user has not accepted the NoLang terms of use. Logging in again will not fix it. Pass on the `error` text and the URL of the agreement page, `terms_url` (in the output's `detail`; it is also on one line at the end of `error`), as is, and continue after the user logs in there and accepts the terms (`nolang doctor` shows 「ログイン済み OK・利用できる NG」, "logged in OK, usable NG").
- On SSH and containers, the same `--background` uses device authorization automatically. Port forwarding is not needed. On servers that do not support it, it falls back to browser authorization. If that fallback ends in a connection error, **do not redo the login**; have the user paste the URL from the address bar after allowing, and complete the pending login with `nolang auth complete '<URL>'`. You can force browser authorization with `--browser --background`, and the older manual method started with `--no-browser` uses the same `complete`.
- Exit code 4 (cannot connect) → tell the user the result of `nolang doctor` (the endpoint is `api` in `nolang doctor`; production is `https://api.no-lang.com`).

## M. Use specific assets (only when the request includes 「この写真・この動画」 ("this photo / this video"), 「この曲」 ("this song") or 「この声」 ("this voice"), or the user gives you a local file)

- Local file → send it to the user's own assets with `nolang assets upload <file>…` and get a `ref` (`id=<uuid>`) (a video waits for processing to finish, so it takes tens of seconds). MCP cannot carry file contents, so upload with the CLI. Audio (mp3, m4a, wav…) is sent as brought-in audio and is used with `nolang make --speech <id>` (§S).
- Choose from NoLang's assets → `nolang assets search <kind> '<description or name>'` (on MCP, `nolang_assets_search(kind, q)`). For things the user uploaded, add `--mine` (`scope="mine"`). kind = `image` `footage` `bgm` `soundeffect` `speaker` `avatar` `font`. You can check the content with `preview_url`.
- When making with the studio, write the `ref` and where to use it in the request text. When you write the draft yourself, write the `ref` in the position given by `usage` in the response: image and video assets = `image name = id=…` at the root and `content: @name` where it is placed (video assets also `play: loop`); BGM = `bgm#name id=…`; sound effects = `sound name = id=…` or `[♪id=…]` in a line; speakers = `cast name = id=…`; character portraits = `cast name = "voice description" avatar="name"`; fonts = `font "name weight"`.
- Use only the full-length `id=<uuid>` (8-digit ids and `file=name` cannot be used on this path). If an id cannot be read, check stops with `DEFECT:ASSET_UNREADABLE`.
- Where there is no specific asset, write a description (pictures are generated; voices, BGM, sound effects and fonts are chosen from the catalog based on the description).

## Output and exit codes

Results go to stdout as JSON; progress goes to stderr. Exit codes: 0 success / 1 defect in the draft or generation failure / 2 usage / 3 not logged in / 4 connection.
